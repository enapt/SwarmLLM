# SharedState, live config and credits

Invariants this codebase has paid to learn. Each heading is the rule; the text
under it is what to do. The evidence — what the rule replaced, what it was
measured at, and what a change must keep — lives in `docs/invariants/`.

**This file loads only when you touch the code it governs.** Read the linked
`docs/invariants/` topic file before changing code a rule names.

(always loaded). Per-field rules:

- `state.connected_networks` — `DashMap<NodeId, NetGroup>` on the root (#339): the network each node in `connected_node_ids` connects from; written ONLY by the network manager beside `connected_node_ids` (Identify inserts, the last close removes), read ONLY by `SharedState::holder_standing` — the one answer to where a part's holder stands (the registry's full lists and age-out, `holder_counts`). → `docs/invariants/network.md` § "A full holder list"
- `state.peers_own_versions` — `DashMap<NodeId, String>` on the root: the release each CONNECTED node stated itself (its Identify agent version — libp2p's own agent, every release before v0.3.271, read as v0.3.270 at most by `swarm_use::release_in_agent` — or a capability it sent direct), the newest winning; written ONLY by `SharedState::note_peers_own_version` (the identify handler; dispatch through `note_capability_heard`, Direct and connected only), removed ONLY by `forget_peers_own_version` (the network manager, on the last close), read ONLY by `cut_off_verdict`. ## A platform predicate answers "what kernel is this", not "where am I running"

**`config::network::wsl_network_adaptation(is_wsl2, in_container, mirrored)` is the one decision** about WSL2 network overrides (`None` / `Mirrored` / `NatSafeDefaults`). `is_wsl2()` is true inside a Docker container on Windows (#640; the SECOND too-broad predicate after #161), so keep `running_in_container()` strict and ask what else inherits a signal before a platform predicate chooses settings.

## A partial config update builds on the FILE, not on what the daemon remembers

`api::admin::base_for_partial_update` is the base for `PUT /api/admin/config`: the parsed `config.toml` when it parses, the live config otherwise — never `cfg()`, never a refusal. ⚠ **`SharedState::make_config_live` is the live config's one production writer** — the dashboard save, `reload_config` and SIGHUP, each with the file it wrote or re-read (`config::read_config_file`); a writer that is not the file needs this rule revisited. Test `a_reload_makes_every_setting_in_the_file_live`. **What a subsystem keeps OUTSIDE `cfg()` is set there too**, from the live config just stored (`apply_what_subsystems_hold`: the worker threads, `models.auto_manage_enabled`, the model processes' activation compression) — never in one handler from its request (a reload reached neither, v0.3.259 review); test `a_config_made_live_sets_what_subsystems_keep_outside_it`. Command-line overrides of a live setting (`--no-update-check`, `--anchor`) must be re-applied inside `apply_live_config` from the boot snapshot (FUTURE_WORK #107).

→ `docs/invariants/state-and-config.md` § "A partial config update builds on the FILE, not on what the daemon remembers"

## A node asked to stop does not restart into its update (2026-10-14, #271)

**`update_restart::restart_into(state, exe, &drained)`** is the only way to restart into an update (`exec_into` is private) and refuses once `SharedState::shutdown` has been asked: a stop that lands while an update downloads, drains or installs — inside the supervisor's 10 s grace too — must not become a restart. Both restart paths (the automatic install, the dashboard's Apply & Restart) go through it; `install_and_restart` also asks before installing and after the drain. Guards `a_node_asked_to_stop_is_not_restarted_into_its_update`, `a_node_asked_to_stop_does_not_install_and_restart_into_its_update`. **It closes every connection before the exec** (2026-11-05, #407): `state.events.close_before_restart` (`CloseBeforeRestart`) is asked ONLY by `restart_into` and answered ONLY by the network manager's loop (`close_every_connection`), at most `CLOSE_BEFORE_RESTART_WAIT`; the stop is asked again after it. Tests `a_restart_closes_every_connection_before_it_execs`, `a_stop_asked_while_connections_close_is_not_a_restart`. **The drain before it counts work IN FLIGHT** (`SharedState::active_inference_load` beside `active_pipelines`), never `serving_models`, whose entries are permanent (prune's `last_served_at`): every update of a node that had served a peer waited the whole 600 s (field report 2026-11-08); test `a_model_served_earlier_does_not_hold_an_update`. **And a reply held between two forwards** (`ModelProcessPool::models_with_inflight_requests` → `WorkerHandle::in_use`): a peer's split reply has nothing in flight here between its words, and the in-flight count alone restarted mid-reply; test `a_peers_reply_between_two_forwards_holds_an_update`. **And it stops ADMISSION first** (2026-11-12, #444): from its start `peer_work_hold_now` answers `PeerWorkHold::Updating` — a peer's new request refused out loud, running work served, the capability withdrawn and broadcast at once (`UpdateDrain::started`) — until the drain's `Drained` drops; `restart_into` REQUIRES it, so no restart skips the drain or lets new work in before the exec, and a restart that never comes gives the work back. Test `an_update_takes_no_new_work_from_other_computers_while_it_drains`. → `docs/invariants/state-and-config.md` § "The drain stops new work for other computers first"

→ `docs/invariants/state-and-config.md` § "A node asked to stop does not restart into its update"
