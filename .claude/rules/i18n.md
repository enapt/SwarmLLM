# i18n Translation Rules

**This file loads only when you touch the code it governs** — `frontend/`, plus
the Rust files that MINT i18n keys (`error.rs` hint keys, `wishlist.rs::i18n_key`,
tier labels in `reference.rs`). A new key from either side must be translated
into all 21 locales; there is no English fallback.

## When updating UI text

When modifying any user-facing text in `frontend/index.html` or `frontend/js/components/*.js`:

1. **Check `frontend/i18n/en.json`** — if the text has a translation key, update the English value there too
2. **Update all translation files** — run through `frontend/i18n/*.json` and update the corresponding key in every language file
3. **New strings** — if adding new UI text, add a key to `en.json` first, then add translations to all other language files
4. **Add `data-i18n` attributes** — static HTML elements should use `data-i18n="key"` for text, `data-i18n-placeholder` for placeholders, `data-i18n-title` for titles

## Translation files

- Located in `frontend/i18n/{lang}.json`
- Flat key structure with dot namespacing (e.g., `"nav.chat"`, `"setup.welcome"`)
- Plurals use `_one`/`_other` suffix convention
- Interpolation uses `{variable}` placeholders
- `_lang` key = native language name, `_dir` key = text direction (`ltr`/`rtl`)

## Available languages (21)

en, es, fr, de, pt, it, nl, ru, zh, ja, ko, ar, tr, pl, sv, th, hi, vi, id, uk, cs
